# GUI.for.SingBox Custom — P0

Источник требований: `Codex_GUI_for_SingBox_Custom_Prompt.md`. Целевая платформа: Windows x64. Задачи выполняются последовательно с учетом зависимостей; после каждой здесь фиксируются изменения, проверки, ограничения и следующий шаг. Незавершенные критерии не считаются выполненными по результату одной сборки.

## 1. Аудит и контрольная сборка — IN_PROGRESS

Проверить состояние Git, архитектуру профилей, подписок, плагинов, генератора, Modes, bridge, ядер, тестов и сборки; зафиксировать ограничения и исходный результат.

Результат: ветка `main`, origin `GUI-for-Cores/GUI.for.SingBox`; исходная рабочая копия была чистой. `frontend/src/utils/generator.ts` генерирует конфиг, `stores/subscribes.ts` обрабатывает подписки, `stores/plugins.ts` выполняет хуки, `stores/kernelApi.ts` управляет процессом и Clash API, `hooks/useCoreBranch.ts` устанавливает official stable/alpha, Go bridge запускает процессы и выполняет файловые операции. UI: Home, Settings, Subscribes, Profiles. `pnpm install --frozen-lockfile` и исходный `pnpm run build` успешны. Go и Wails отсутствуют в PATH; Windows-сборка и интеграционные тесты не проверены. Исследование существующих тестов и полный аудит совместимости остаются в задачах ниже.

## 2. Безопасность существующей установки и проверки запуска — IN_PROGRESS

Проверить и исправить текущий загрузчик: проверка архива и бинарника до замены, отказ от изменения работающего файла, восстановление предыдущей версии при ошибке, корректная отмена и контрольная сумма только при наличии достоверного digest. Перед запуском проверять именно используемую конфигурацию совместимой командой ядра; сохранять настраиваемые аргументы и показывать диагностику. Добавить тесты отказов, отмены, отсутствия digest и работающего процесса.

Результат на текущий момент: `useCoreBranch.ts` распаковывает и выполняет `version` до замены, проверяет работающую ветку и пытается восстановить резервную копию; `kernelApi.ts` вызывает `check` до запуска. Frontend build проходит. Реальные установка и откат не проверены; поведение пользовательских аргументов и отсутствие digest требуют проверки. Задача открыта.

Дополнение: отсутствие digest больше не вызывает исключение; пользователь получает предупреждение об отсутствии проверки суммы. Некорректный digest отклоняется, корректный SHA-256 передается загрузчику. `pnpm run build` прошел; сценарии скачивания и отмены еще требуют интеграционной проверки.

Дополнение: `bridge/net.go` отклоняет неуспешные HTTP-ответы до создания файла и удаляет частичный файл при ошибке записи или отмене. `git diff --check` прошел; Go-тесты не запущены, поскольку Go не найден в PATH. Необходимы тесты с HTTP-сервером и реальная проверка отмены.

Дополнение: отмена больше не запускает отложенное удаление, способное затронуть повторную загрузку; очистка обработчика прогресса и состояния загрузки выполняется также при ошибке. `pnpm run build` прошел. Интеграционная проверка отмены остается открытой.

Добавлен `bridge/net_download_test.go`: локальный HTTP-сервер проверяет успешную загрузку с SHA-256 и без него, неверную сумму и HTTP 404, в том числе отсутствие файла после ошибки. Тест пока не запускался: Go не обнаружен в окружении. Проверка отмены и работающего процесса остаются открытыми.

Актуализация: Go 1.27.3 доступен через WSL; `go test ./...` прошел, включая `bridge/net_download_test.go`. Запуск WSL из песочницы отклонен, вне песочницы выполнен. Проверки отмены, работающего ядра и Windows остаются открытыми.

`bridge/io.go` теперь сообщает ошибки при распаковке ZIP/TAR и отклоняет небезопасные пути и неподдерживаемые типы вместо молчаливого успеха. `bridge/io_archive_test.go` проверяет обычный ZIP и попытку выхода из каталога; `go test ./...` в WSL прошел. Проверка реальных архивов всех существующих сценариев, отмены и работающего ядра остается открытой.

## 3. Источники релизов и возможности ядер — TODO

Подтвердить официальные источники SagerNet/sing-box и Leadaxe/sing-box-lx, форматы Windows amd64 архивов, контрольные суммы и сопутствующие файлы. Покрыть разбор версий, отсутствующие релизы и сетевые ошибки тестами.

Начато: `coreCapabilities.ts` извлекает версию и явно сообщенные binary build tags; отсутствие списка трактуется как неизвестность. `useCoreBranch.ts` использует общий разбор версии. Две проверки `node --experimental-strip-types --test tests/coreCapabilities.test.ts` и `pnpm run build` прошли. Репозиторий LX документирует build tag `with_xhttp` и SHA256SUMS: https://github.com/Leadaxe/sing-box-lx . Получение GitHub API из текущей PowerShell-среды завершилось ошибкой TLS; реальные бинарники, матрица версий и использование capabilities в генерации еще не проверены. Задача остается открытой.

Настройки ядра теперь показывают наличие, отсутствие или неизвестность тега `with_xhttp` из вывода бинарника (`useCoreBranch.ts`, `BranchDetail.vue`, локализации); frontend build прошел. Это только обнаружение тега, не подтверждение совместимости отдельных полей XHTTP.

`coreReleases.ts` содержит адреса публичных источников и проверку имени Windows amd64 архива; существующий official-загрузчик использует общий адрес. Публичный API LX через WSL подтвердил asset `sing-box-1.14.4-lx.33-windows-amd64.zip` и digest. Тесты `coreCapabilities.test.ts`, `coreReleases.test.ts` и `pnpm run build` прошли. `gh auth status` сообщает недействительный сохраненный токен; WSL curl получает публичные данные без него. Список и установка LX в приложении еще не реализованы.

Текущий проход: `useCoreLx.ts` получает список LX-релизов и точные Windows amd64 assets из публичного API, проверяет SHA-256 из digest или SHA256SUMS и устанавливает содержимое архива в отдельный каталог версии. `LxCore.vue` добавляет выбор релиза, установку и выбор установленной версии. `kernelApi.ts` запускает и проверяет выбранный исполняемый файл; official stable/alpha сохранены. Настройки сохраняют `branch` и `lxVersion`. Настоящий релиз v1.14.4-lx.33 скачан через gh: сумма совпала, проектный Go-распаковщик извлек exe и libcronet.dll, Windows exe успешно прошел `version`, `check` и короткий запуск с минимальной конфигурацией. WSL `go test ./...` и frontend build прошли. Полное взаимодействие через собранный Windows GUI, включая сбои загрузки и восстановление после перезапуска, еще не проверено; задачи 3–6 остаются открытыми. Проект Wails для Windows в этом окружении не собирался: кросс-компилятор в WSL не найден.

Для LX генератор использует поведение стабильной ветки, а не удаляет настройки TUN, как для alpha; frontend build повторно прошел. Проверка существующих профилей на разных версиях LX остается открытой.
